Two independent nginx edges serve app.admv.test with the SAME trusted cert:
  PRIMARY edge  10.7.25.158  -> X-Edge: mac2
  STANDBY edge  10.7.24.165  -> X-Edge: standby   (on Dikshant's laptop, Mac 4)

BEFORE cutover:
  team DNS (Vaibhav) app.admv.test -> 10.7.25.158 (primary), TTL raised to 120

CUTOVER: Vaibhav changed the DNS record app.admv.test -> 10.7.24.165 (standby)
  team DNS now returns            -> 10.7.24.165
  fresh lookup (dig, no cache)    -> 10.7.24.165
  NEW client path to standby      -> X-Edge: standby
  service via DNS (by name)       -> HTTP 200

RESULT: new DNS lookups are migrated to the standby edge. During the TTL window,
clients that cached the old answer keep hitting the primary edge until expiry — the
same TTL-staggering proven in Extension B (see B-dns-ttl.txt), here applied to the
EDGE tier. This mitigates the single point of failure identified in Extension D.

ROLLBACK (restore normal): on Vaibhav -> app.admv.test back to 10.7.25.158, TTL 30,
restart dnsmasq;  on Dikshant -> sudo nginx -s stop.
